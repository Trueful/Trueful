## 作業内容

### `writeJsonFile` のアトミック書き込み化

`fs.writeFileSync(path, data)` による直接上書きを、tmpファイルへの書き込み→`renameSync`による切り替えの2段階に変更した。設計判断の詳細はADR-013参照。

対象:
- `app/src/main/services/workspaceFile.ts` — `writeJsonFile` の実装変更

```typescript
import fs from 'fs'

class WorkspaceFileError extends Error {
  path: string
  error: NodeJS.ErrnoException

  constructor(path: string, error: NodeJS.ErrnoException) {
    super(error.message)
    this.path = path
    this.error = error
  }
}

export function writeJsonFile(path: string, data: unknown): string {
  const tempPath = path + '.tmp'
  const returnJson = JSON.stringify(data)
  try {
    fs.writeFileSync(tempPath, returnJson)
    fs.renameSync(tempPath, path)
  } catch (error) {
    throw new WorkspaceFileError(path, error as NodeJS.ErrnoException)
  }
  return path
}
```

`catch (error)` で受け取る `error` の型は `unknown` になるため、`NodeJS.ErrnoException` への型アサーション（`as`）を使用した。`WorkspaceFileError` の中で実際にアクセスしているのは `error.message` と `error` 自体の保持のみで、`.code` 等のNode.js固有プロパティには触れていないため、アサーションが外れていた場合の実害は小さいと判断した。

### `services/` 層のファイル分割方針の整理

`workspaceFile.ts` の命名（`workspace`（対象）+ `File`（手段））をパターンとして、`services/` 配下は「技術手段（SQLかファイルか）」ではなく「対象（Workspace、Pattern Trust Ledgerなど）」でファイルを分割する方針に統一した。これにより、Workspace用のSQL操作をまとめるファイルは `workspaceDB.ts` と命名することにした。実装はまだ着手していない。

## 問題と対処

### pnpmが古いバージョン（9.15.0）で動作していた

- **症状**: `pnpm add` 時に `The following dependencies have build scripts that were ignored` という警告が出た上、`pnpm approve-builds` を実行しても `Command "approve-builds" not found` となった。
- **原因**: `which pnpm` で確認したところ `/usr/local/bin/pnpm` が使われており、これは `nvm` 管理下のNode.jsとは無関係な、環境構築初期（2024年12月時点のシンボリックリンク）に乱雑にインストールされた旧バージョンだった。`PATH` の中でこの古い方が `~/Library/pnpm` より先に解決されていた。
- **対処**: `sudo rm /usr/local/bin/pnpm` で古いシンボリックリンク（実体は削除せずリンクのみ）を削除し、`PATH` 上で新しい `pnpm`（`pnpm self-update` で導入した `12.3.4`）が解決されるようにした。

### `better-sqlite3` のネイティブビルドが `node-gyp` の段階で失敗

- **症状**: `pnpm install` 時、`better-sqlite3` の再ビルド中に `make: error` および `Error loading required libraries ... Symbol not found: _XPCTypeBool` というエラーで失敗した。
- **原因**: Xcodeのコマンドラインツール（またはXcode自体）が不完全な状態になっていたと推測される。同時期にXcode.appの起動自体もクラッシュしていたことが判明し、症状が一致する。根本原因（何が不整合を起こしたか）は未特定。
- **対処**: `~/Library/Developer/Xcode/DerivedData` と `~/Library/Caches/com.apple.dt.Xcode` を削除し、`sudo xcodebuild -runFirstLaunch` と `xcode-select --install` を実行してコマンドラインツールを再インストールした。再インストール後、同様の `Symbol not found` エラーは再発していない。

### pnpm 12系での `onlyBuiltDependencies` 設定が反映されない

- **症状**: `app/package.json` の `"pnpm": { "onlyBuiltDependencies": [...] }` に `better-sqlite3` を追加しても、`[WARN] The "pnpm" field in package.json is no longer read by pnpm` という警告とともに無視され続けた。
- **原因**: pnpm 10.26以降、`onlyBuiltDependencies` の設定場所が `package.json` の `pnpm` フィールドから、専用の `pnpm-workspace.yaml`（または `allowBuilds` という新設定）に移行していた。
- **対処**: `app/pnpm-workspace.yaml` を新規作成し、`allowBuilds` に `electron` / `esbuild` / `better-sqlite3` / `electron-winstaller` を許可リストとして登録した。`package.json` 側の古い `pnpm.onlyBuiltDependencies` フィールドは削除していない（未解決事項参照）。

### `.gitignore` のパス指定ミス（二重パス）

- **症状**: `app/.gitignore` に `app/src/main/_experiments/*.js` と書いたが、`git status` で `_experiments/test.js` が無視されず表示され続けた。
- **原因**: `.gitignore` の記述場所が `app/.gitignore`（`app/` を基準とする相対パス解決）であるにもかかわらず、`app/` を接頭辞に含めたパスを書いてしまい、実質 `app/app/src/main/_experiments/*.js` という存在しないパスを指定していた。
- **対処**: `app/` の接頭辞を外し、`src/main/_experiments/*.js` / `src/main/_experiments/*.sqlite3` に修正した。

## 判断ログ

| 判断 | 選択 | 理由 |
| --- | --- | --- |
| tmpファイル名の決定方式 | 固定名（`path + '.tmp'`） | UUID化しても「後勝ち」問題は解決しないため、単一プロセスからの逐次呼び出しが前提の現状ではシンプルさを優先 |
| `renameSync` 失敗時のtmpファイル後始末 | 何もしない（次回書き込みで上書きされることに委ねる） | 明示的な削除処理を足すコストに対して、実害が小さいと判断 |
| `better-sqlite3` の動作確認コードの扱い | 削除せず `_experiments/` に保存 | 今後同様のSQL操作を書く際の参照資料として価値があると判断 |
| `import` 方式 | `import * as Database from 'better-sqlite3'` | `export =` 形式のモジュールに対し `esModuleInterop` なしで動かすため。プロジェクト全体の `tsconfig.json` を変更せず、検証コード側で完結させる方針を優先 |
