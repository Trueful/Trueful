# AI Development Rules

AIエージェント（Claude Code, Cursor 等）がTruefulのコードベースを編集する際の厳格なルールです。このファイルを読み込んだAIは、以下の指示に必ず従うこと。

## Never
* **勝手に設計変更しない**: コードの都合で仕様を変えてはいけません。
* **Architectureを変更しない**: アーキテクチャの変更は人間によるADRの承認が必要です。
* **Philosophyを変更しない**: Truefulの思想に反するコードを追加してはいけません。
* **推測で実装しない**: 仕様が不明確な場合は、推測でコードを書かずに必ず人間に質問してください。

## Always
* **TODOを書く**: 未解決の課題や仮実装の部分には明確に `// TODO: ` を残してください。
* **理由を書く**: 複雑なロジックや、一般的なプラクティスから外れる実装には、コードコメントで理由（Why）を記載してください。
* **型を書く**: TypeScriptの `any` は原則禁止です。インターフェースや型定義を明確にしてください。

## Rules

* **Rule 1**: 仕様より推測を優先してはいけない。分からなければ質問する。
* **Rule 2**: `Architecture.md` を最優先とする。コードよりArchitectureが正しい。
* **Rule 3**: `Philosophy.md` に反する実装は禁止。
* **Rule 4**: 新しい依存パッケージの追加は原則禁止。追加が必要な場合は必ず理由を提示し、許可を得る。
* **Rule 5**: 既存の命名規則は変更しない。
* **Rule 6**: 他の人が書いたTODOを勝手に削除しない。完全に解決した時のみ削除する。
* **Rule 7**: コードコメントで仕様を書かない。仕様は `docs/` へ。コードには「なぜそう実装したか」を書く。
* **Rule 8**: コードを書く前に、必ず `Plan` (変更のステップ) を記述・出力して確認を得る。
* **Rule 9**: PRや一回の変更サイズは500行以内に抑える。
* **Rule 10**: リファクタリングと機能追加を混ぜない。
